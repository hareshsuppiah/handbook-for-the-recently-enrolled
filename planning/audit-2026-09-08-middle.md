# Content and template audit: parts 05–08 and all templates

Reviewed and implemented on 8 September 2026. This is an editorial and usability review of all 12 chapters in parts 05–08 and all 33 template pages. It does not certify every cited source as newly verified, or establish the book as a universal institutional procedure. The root review handles the full external scan, rendered site, contribution screenshots, image inspection, deployment and agent instructions.

## Method and findings before editing

Read every assigned source in full, `planning/style-guide.md`, and the `graduate-research-reader-editor` skill and its style model. Findings were sent to the coordinating agent before source edits.

The existing chapters had recognisable situations, useful examples, evidence and important safeguards. Most had already received a reader-oriented rewrite. Their remaining weakness was instructional: long inventories sometimes arrived before the reader could see how to apply a distinction. Several technical terms were correct but insufficiently explained. More generic encouragement or a wholesale change of voice would have made the chapters longer without teaching the missing step.

The templates were substantively useful but difficult to take away and use. Many opened directly on a blank register; wide tables copied poorly into ordinary notes. Some examples looked like completed records without an explicit illustrative label. Two substantive inconsistencies required correction: the authorship material linked to a research-contribution statement as though it were an author-role declaration, and an action-register example labelled an evidenced completed booking as active.

## Preservation map

- Retained every existing citation and practical-resource link across these 45 files. The authorship links now explain their actual purpose.
- Retained all original explicit anchors. The renamed design-inference heading carries its old anchor.
- Retained the original template forms, headings, examples, scenario tests, local checks and escalation conditions as the readable reference. Added one collapsible plain-text blank form to each page so copying and downloading can target an unambiguous block.
- Retained ethics, privacy, consent, authority, safety, data-governance, authorship and specialist-advice boundaries. The storage migration example now also preserves incident evidence and requires verification of destination copies before authorised source removal.
- Kept numerical, dated and person-labelled worked examples illustrative. No example is offered as a verified student record or universal threshold.
- Retained the research/method/institution distinctions. No new substantive legal or policy permission was introduced.
- Checked standalone copy forms separately: where page-level privacy, authorship, incident, review or local-policy instructions were essential to reuse, those instructions also appear in the blank copy.

## External check and runnable example

Opened these primary sources on 8 September 2026 for the newly added Quarto teaching material:

- [Quarto: Using R](https://quarto.org/docs/computations/r.html): executable code blocks, R setup and rendering.
- [Quarto: Execution Options](https://quarto.org/docs/computations/execution-options.html): escaped teaching examples and execution options.
- [Quarto: Managing Execution](https://quarto.org/docs/projects/code-execution.html): cache/freeze behaviour and recomputation when external inputs change.

The first literal-code render exposed a real defect: placing executable R inside a four-backtick example alone still allowed execution. Replaced the inner and inline expressions with Quarto's documented double-brace escapes. The rendered teaching snippet now contains copyable single-brace executable syntax and preserves the inline expressions.

In a separate temporary folder, copied and rendered the example with R/Quarto. It produced three rows and `The total is 12 across 3 groups.` Changed the last input from 6 to 8, rendered again, and checked `The total is 14 across 3 groups.` Inspected the literal teaching snippet separately to ensure it contained code rather than inserted execution output. This is a test of the teaching example, not an analysis of research data.
